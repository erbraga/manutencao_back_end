## Objetivos
A aplicação atual é o frontend de um sistema de  manutenção de veículos para o formato de microserviços e caso não o faça deverá seguir  os requisitos descritos neste documento.

### Requisito 1:

 Implementar uma API REST em Python, como Flask ou FastAPI, com pelo menos 4 rotas e documentação em Swagger. Deve existir pelo menos uma para cada um dos métodos: POST, PUT/PATCH, DELETE, GET.


### Requisito 2:

Deve haver um arquivo  README.md que deve conter, no mínimo, as seguintes informações:
- Título e uma breve descrição do projeto;
- Instruções de instalação, tais como: descrever as etapas necessárias para que os desenvolvedores possam configurar o ambiente local, instalar as dependências, definir os comandos de inicialização, etc.
- Certifique-se de que o arquivo README.md esteja bem formatado, com cabeçalhos, listas e formatação de texto, para tornar a documentação mais fácil de ler.
- É obrigatório produzir uma imagem (fluxograma) que ilustre a arquitetura da aplicação desenvolvida. Use, como exemplo, algum cenário.

### Requisito 3:
Deve haver um Dockerfile para cada componente desenvolvido com todo o processo de implementação da solução em um contêiner Docker.

### Requisito 4:
Criatividade e Inovação:​
A API deve adicionar funcionalidades extras além do CRUD básico (ex.: autenticação, ordenação, filtros, paginação).

### Requisito 5:
Implementação de uma API REST com pelo menos 4 rotas e documentação em Swagger.

### Requisito 7:
Uso da API externa brasilapi.com.br para implementar busca na tabela FIPE.

### Requisito 8:
Apresentar, na documentação da interface ou da API principal, a API externa a ser utilizada deixando claras informações como a licença de uso (se aplicável), o cadastro (se necessário) e as rotas utilizadas.
O consumo da API externa não pode causar o redirecionamento para outra aplicação. Ou seja, você deve consumir e tratar os dados da componente externa na sua aplicação

### Requisito 10:
Cada módulo (interface e/ou API) deve ter um repositório público separado no GitHub.
A estrutura de pastas e arquivos deve ser organizada de forma clara.
Nomes de arquivos, pastas e componentes devem seguir convenções de boas práticas (ex.: CamelCase para componentes React, snake_case para arquivos Python).
